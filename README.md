# Excel Template Converter

เว็บสำหรับเตรียมข้อมูลทะเบียนสินทรัพย์จากไฟล์ Excel หลายรูปแบบให้เป็น
ไฟล์ `.xlsx` ตาม Template กลาง พร้อมตรวจสอบข้อมูลก่อนนำไปใช้กับระบบบริหาร
สินทรัพย์ขององค์กร

โปรเจกต์นี้ไม่ได้มีหน้าที่บริหารสินทรัพย์โดยตรง แต่ทำหน้าที่เป็นสะพานระหว่าง
ไฟล์ Excel เดิมของแต่ละหน่วยงานกับระบบปลายทางที่ต้องการข้อมูลในรูปแบบเดียวกัน

## ทำไมต้องมีระบบนี้

ในองค์กรหนึ่งมักมีข้อมูลสินทรัพย์กระจายอยู่ในไฟล์ Excel หลายชุด เช่น
ทะเบียนครุภัณฑ์ รายการสินทรัพย์ใหม่ รายการรับโอน หรือไฟล์จากแต่ละสำนักและฝ่าย
แต่ละไฟล์อาจใช้ชื่อคอลัมน์ ตำแหน่งหัวตาราง และรูปแบบวันที่หรือจำนวนเงินไม่เหมือนกัน

ตัวอย่างข้อมูลเดียวกันอาจถูกเรียกต่างกัน:

| ไฟล์ต้นทาง | ความหมายใน Template กลาง |
| --- | --- |
| เลขครุภัณฑ์ / รหัสพัสดุ / Asset Code | รหัสสินทรัพย์ |
| รายการ / ชื่อครุภัณฑ์ / Model Name | ชื่อสินทรัพย์ |
| ราคาที่ได้มา / ราคาซื้อ / Cost | มูลค่า |
| ผู้รับผิดชอบ / ผู้ใช้งาน | ผู้ถือครอง |

หากนำไฟล์เหล่านี้เข้าสู่ระบบปลายทางโดยตรง ข้อมูลอาจอยู่ผิดคอลัมน์ ขาดข้อมูลสำคัญ
หรือมีรูปแบบที่ระบบอ่านไม่ได้ Excel Template Converter จึงช่วยอ่าน จัดโครงสร้าง
จับคู่ และตรวจสอบข้อมูลก่อนสร้างไฟล์มาตรฐาน

## ระบบนี้อยู่ตรงไหนในงานขององค์กร

```text
Excel เดิมจากแต่ละหน่วยงาน
        |
        v
Excel Template Converter
อ่านชีต -> หา Header -> จับคู่คอลัมน์ -> ตรวจข้อมูล
        |
        v
เจ้าหน้าที่ตรวจตัวอย่างและแก้เฉพาะจุดที่จำเป็น
        |
        v
ไฟล์ Excel ตาม Template กลาง
        |
        v
นำเข้าสู่ระบบบริหารสินทรัพย์ขององค์กร
        |
        v
ทะเบียนสินทรัพย์กลาง
        |
        +--> ติด RFID/QR และตรวจนับ
        +--> ยืม-คืนหรือโอนย้าย
        +--> แจ้งซ่อมและติดตามสถานะ
        +--> จำหน่ายสินทรัพย์
        `--> คำนวณค่าเสื่อมและจัดทำรายงาน
```

ระบบบริหารสินทรัพย์ปลายทางอาจเป็นระบบภายในองค์กรหรือระบบจากผู้ให้บริการภายนอก
ทั้งนี้โปรเจกต์นี้ยังไม่มีการเชื่อม API หรือส่งข้อมูลเข้าสู่ระบบปลายทางอัตโนมัติ
ไฟล์ที่ดาวน์โหลดคือไฟล์สำหรับให้เจ้าหน้าที่ตรวจสอบและนำเข้าตามขั้นตอนขององค์กร

## ตัวอย่างการใช้งานจริง

สมมติหน่วยงานมีข้อมูลต้นทางดังนี้:

| เลขครุภัณฑ์ | รายการ | ราคาที่ได้มา | หน่วยงาน |
| --- | --- | ---: | --- |
| 001-66-0045 | คอมพิวเตอร์ Dell | 25,000 | งานการเงิน |

ระบบจะช่วยจับคู่ข้อมูลเข้าสู่ช่องมาตรฐาน เช่น `รหัสสินทรัพย์`, `ชื่อสินทรัพย์`,
`มูลค่า` และ `งานที่รับผิดชอบ` จากนั้นเจ้าหน้าที่สามารถตรวจและเติมข้อมูลอื่น เช่น
ผู้ถือครอง อาคาร ห้อง วันที่ได้รับ สถานะ หรือหมายเลขเครื่อง ก่อนสร้างไฟล์ใหม่

เมื่อไฟล์นี้ถูกนำเข้าสู่ระบบบริหารสินทรัพย์ รายการดังกล่าวจึงสามารถถูกผูกกับ
RFID/QR Code ใช้ตรวจนับ ระบุตำแหน่ง บันทึกผู้ถือครอง และติดตามประวัติได้

## ขอบเขตของโปรเจกต์

| ระบบนี้ทำ | ระบบนี้ยังไม่ได้ทำ |
| --- | --- |
| อ่านไฟล์ `.xlsx` และ `.xls` | บริหารการยืม-คืน โอนย้าย ซ่อม หรือจำหน่าย |
| วิเคราะห์และจำแนกชีต | สแกน RFID/QR Code |
| หาแถว Header และช่วงข้อมูล | คำนวณค่าเสื่อมเป็นระบบบัญชีเต็มรูปแบบ |
| แนะนำการจับคู่คอลัมน์ | เชื่อม API กับระบบปลายทางโดยตรง |
| ให้แก้ Mapping และค่ารายเซลล์ | นำไฟล์เข้าสู่ระบบปลายทางอัตโนมัติ |
| ตัดแถวที่ไม่ต้องการส่งออก | จัดเก็บทะเบียนสินทรัพย์เป็นฐานข้อมูลถาวร |
| ตรวจข้อผิดพลาดและคำเตือน | ยืนยันตัวตนหรือกำหนดสิทธิ์ผู้ใช้ |
| สร้างไฟล์ `.xlsx` ตาม Template | แก้ไขไฟล์ Excel ต้นฉบับของผู้ใช้ |

## ความสามารถหลัก

- รับไฟล์ `.xlsx` และ `.xls` ขนาดไม่เกิน 20 MB
- อ่านทุกชีตและจำแนกประเภทของข้อมูลในแต่ละชีต
- หาแถวหัวตารางและช่วงข้อมูลที่ควรนำมาแปลง
- แนะนำการจับคู่คอลัมน์ต้นทางกับคอลัมน์ใน Template
- ให้ผู้ใช้เปลี่ยน Mapping แก้ค่าเซลล์ หรือไม่นำออกบางแถวได้
- ตรวจข้อมูลสำคัญ เช่น รหัสและชื่อสินทรัพย์ วันที่ ตัวเลข สถานะ และข้อมูลซ้ำ
- ตรวจค่าบางคอลัมน์กับรายการอ้างอิงใน Template
- แสดงตัวอย่างข้อมูลและสรุปข้อผิดพลาดแยกตามชีต
- สร้างไฟล์ Excel ใหม่โดยใช้โครงสร้างและลำดับคอลัมน์ของ Template
- เปลี่ยน Template ที่ใช้งานผ่านหน้า `/settings` ได้

## ขั้นตอนใช้งาน

1. เปิดหน้าเว็บ แล้วอัปโหลดหรือลากไฟล์ Excel ลงในพื้นที่อัปโหลด
2. ระบบอ่าน Workbook วิเคราะห์แต่ละชีต และแนะนำการจับคู่คอลัมน์
3. เลือกชีตที่ต้องการ ตรวจ Preview และดูรายการข้อผิดพลาดหรือคำเตือน
4. แก้ Mapping แก้ค่าเซลล์ หรือตัดแถวที่ไม่ต้องการออก
5. กดตรวจสอบข้อมูลอีกครั้ง
6. เมื่อไม่มีข้อผิดพลาดที่ขัดขวางการส่งออก ให้ดาวน์โหลดไฟล์ที่แปลงแล้ว
7. เจ้าหน้าที่ตรวจไฟล์ผลลัพธ์และนำเข้าสู่ระบบบริหารสินทรัพย์ปลายทาง

ชื่อไฟล์ผลลัพธ์จะอยู่ในรูปแบบ:

```text
converted_template_<ชื่อไฟล์ต้นทาง>.xlsx
```

ไฟล์ต้นฉบับบนเครื่องของผู้ใช้จะไม่ถูกแก้ไข

## การทำงานภายในระบบ

```text
Browser (Frontend :3000)
  |
  |  POST /api/v1/parse
  |  ส่งไฟล์ Excel
  v
Backend API (:3001)
  |
  |-- อ่าน Workbook
  |     |-- .xlsx: Python + openpyxl เป็นตัวเลือกหลัก
  |     `-- .xls หรือกรณี fallback: TypeScript reader
  |
  |-- จำแนกชีตและหา Header
  |-- แปลงข้อมูลเป็นโครงสร้างกลาง
  |-- แนะนำ Mapping และตรวจคุณภาพข้อมูล
  `-- เก็บผลวิเคราะห์ชั่วคราวด้วย analysisId
  |
  v
Browser แสดงชีต Mapping Preview และรายการปัญหา
  |
  |  POST /api/v1/export (mode: validate)
  v
Backend รวม Mapping และค่าที่ผู้ใช้แก้ แล้วตรวจสอบอีกครั้ง
  |
  |  POST /api/v1/export (mode: download)
  v
Backend สร้างไฟล์ตาม Template -> Browser ดาวน์โหลด .xlsx
```

`analysisId` เป็นรหัสอ้างอิงข้อมูลของการอัปโหลดแต่ละครั้ง ข้อมูลการวิเคราะห์
ถูกเก็บในหน่วยความจำของ Backend เป็นเวลา 30 นาที และต่ออายุเมื่อมีการใช้งาน
หาก Backend รีสตาร์ตหรือข้อมูลหมดอายุ ผู้ใช้ต้องอัปโหลดไฟล์ใหม่

เมื่อผู้ใช้แก้ Mapping ค่าเซลล์ หรือรายการแถว ผลตรวจเดิมจะถือว่าไม่ใช่ผลล่าสุด
และต้องตรวจสอบอีกครั้งก่อนดาวน์โหลด

## API หลัก

| Endpoint | ใช้เมื่อ | ผลลัพธ์ |
| --- | --- | --- |
| `POST /api/v1/parse` | อัปโหลดไฟล์ | รายละเอียดชีต Preview Mapping ที่แนะนำ และ `analysisId` |
| `POST /api/v1/reparse-sheet` | กำหนดแถว Header หรือช่วงข้อมูลใหม่ | ผลวิเคราะห์ชีตล่าสุด |
| `POST /api/v1/export` พร้อม `mode: validate` | ตรวจข้อมูลก่อนดาวน์โหลด | ข้อมูลที่แปลงแล้วและรายการปัญหา |
| `POST /api/v1/export` พร้อม `mode: download` | สร้างไฟล์ผลลัพธ์ | ไฟล์ `.xlsx` สำหรับดาวน์โหลด |
| `GET/POST /api/v1/admin/template` | ดูหรือเปลี่ยน Template | สถานะ Template หรือเวอร์ชันใหม่ |
| `POST /api/v1/admin/template/rollback` | ย้อนกลับ Template | เปลี่ยนเวอร์ชัน Template ที่ใช้งาน |

## เริ่มต้นใช้งานสำหรับนักพัฒนา

### สิ่งที่ต้องมี

- Node.js และ npm
- Python 3 และ pip สำหรับตัวอ่าน `.xlsx` ที่แนะนำ

รันคำสั่งต่อไปนี้จากโฟลเดอร์หลักของโปรเจกต์:

```powershell
cd excel-converter
npm.cmd install
python -m pip install -r backend/python/requirements.txt
npm.cmd run dev
```

จากนั้นเปิด <http://localhost:3000>

| Service | URL |
| --- | --- |
| Frontend | `http://localhost:3000` |
| Backend API | `http://localhost:3001` |

Frontend จะส่ง Request ที่ `/api/*` ไปยัง Backend โดยอัตโนมัติ หาก Backend
อยู่คนละ URL ให้กำหนด `BACKEND_URL` ก่อนรันหรือ Build Frontend:

```powershell
$env:BACKEND_URL = "https://api.example.com"
npm.cmd run build
```

### โหมดตัวอ่าน Excel

ตัวแปร `WORKBOOK_EXTRACTOR` ใช้เลือกวิธีอ่านไฟล์:

| ค่า | พฤติกรรม |
| --- | --- |
| `auto` | ค่าเริ่มต้น ใช้ Python กับ `.xlsx` ก่อน และ fallback ไป TypeScript หากใช้ไม่ได้ |
| `python` | บังคับใช้ Python extractor |
| `typescript` | ใช้ TypeScript reader โดยไม่เรียก Python |

ตัวอย่างการกำหนดค่าใน PowerShell:

```powershell
$env:WORKBOOK_EXTRACTOR = "python"
npm.cmd run dev
```

## คำสั่งที่ใช้บ่อย

รันจากโฟลเดอร์หลักของโปรเจกต์:

```powershell
npm.cmd run dev          # รัน Frontend และ Backend สำหรับพัฒนา
npm.cmd run build        # Build Backend แล้วตามด้วย Frontend
npm.cmd run typecheck    # ตรวจ TypeScript ทุก Workspace
npm.cmd test             # รันทดสอบ Backend
npm.cmd run audit:assets # ตรวจไฟล์ Excel ตัวอย่างและสร้างรายงาน
npm.cmd start            # เปิดทั้งสอง Service จาก Production Build
```

รายงานจาก `npm.cmd run audit:assets` จะถูกสร้างที่
`backend/reports/asset-audit.json`

## Template และข้อมูลอ้างอิง

Template เริ่มต้นอยู่ที่ `backend/assets/asset-template.xlsx` และกำหนดคอลัมน์
ปลายทาง เช่น รหัสสินทรัพย์ ชื่อสินทรัพย์ ประเภท ตำแหน่ง ผู้ถือครอง หน่วยงาน
แหล่งงบประมาณ มูลค่า วันที่ได้รับ สถานะ และข้อมูล RFID/QR

ผู้ดูแลสามารถเปลี่ยน Template ผ่านหน้า `/settings` ระบบจะตรวจโครงสร้างไฟล์ก่อน
เปิดใช้งาน และเก็บ Template ที่อัปโหลดไว้ใน `backend/data/templates/` ซึ่งไม่ถูก
Commit เข้า Git

## ข้อจำกัดและความปลอดภัย

- รองรับไฟล์อัปโหลดขนาดสูงสุด 20 MB
- รองรับสูงสุด 100 ชีตต่อ Workbook
- รองรับสูงสุด 50,000 แถวและ 256 คอลัมน์ต่อชีต
- รองรับข้อมูลรวมสูงสุด 1,000,000 เซลล์ต่อ Workbook
- เก็บผลวิเคราะห์พร้อมกันสูงสุด 20 รายการในหน่วยความจำ
- ผลวิเคราะห์มีอายุ 30 นาทีและหายเมื่อ Backend รีสตาร์ต
- ปัจจุบันยังไม่มีระบบยืนยันตัวตนหรือกำหนดสิทธิ์ผู้ใช้
- หน้า `/settings` และ API สำหรับเปลี่ยน Template ยังไม่มีการป้องกันด้วยสิทธิ์ผู้ดูแล
- หากไฟล์มีข้อมูลภายในองค์กร ควรติดตั้งระบบในเครือข่ายที่ควบคุมการเข้าถึงได้
